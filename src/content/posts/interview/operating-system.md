# 系统基础

## 定义

> **操作系统（Operating System, OS）** 是计算机系统中管理硬件和软件资源的中间层系统软件，屏蔽了底层硬件的复杂性，并且为用户和应用程序提供了便捷、安全的接口与交互环境。

## 主要功能

- **进程管理**：负责创建、调度、同步与终止进程。进程是正在运行的程序实例，每个进程拥有独立的地址空间和系统资源。
- **内存管理**：负责为进程动态分配与回收物理内存，通过虚拟内存技术实现地址空间隔离与扩充。
- **文件管理**：提供创建、删除、读写文件的能力，组织文件的树状分层存储结构（如目录与权限控制）。
- **设备管理**：通过设备驱动程序控制和统一调度计算机的各种硬件设备（如键盘、鼠标、磁盘、网卡、打印机等）。

# 进程管理

## 并行与并发的区别

- **并发（Concurrency）**：指在一段时间内，多个任务都会被处理；但在某一时刻，只有一个任务在 CPU 核心上执行。单核处理器主要通过时间片轮转（Time Slicing）实现并发。例如有两个进程 A 和 B，A 运行一个时间片之后切换到 B，B 运行一个时间片之后又切换到 A。因为切换速度极快，在宏观上表现为在一段时间内能“同时”运行多个程序。
- **并行（Parallelism）**：指在同一时刻，有多个任务在同时执行。这需要多核处理器的物理硬件支持，不同的程序被分配到不同的物理 CPU 核心上同时运行，在微观上也是真正意义上的物理同时执行。

## 进程上下文切换

上下文切换（Context Switch）是操作系统在多任务处理环境中，将 CPU 从一个进程切换到另一个进程的过程。通过让多个进程共享 CPU 资源，使系统具备并发多任务处理能力。

进程上下文切换通常包含以下步骤：

1. **保存当前进程上下文**：操作系统将当前进程的 CPU 寄存器内容、程序计数器（PC）、程序状态字（PSW）等关键运行状态保存到该进程的 PCB（进程控制块）中；
2. **选择下一个进程**：调度程序根据特定的调度策略选择下一个将要分配 CPU 的就绪进程；
3. **恢复目标进程上下文**：从目标进程的 PCB 中恢复 CPU 寄存器与上下文执行现场；
4. **切换虚拟内存映射**：切换页表基地址寄存器（如 x86 的 CR3），使 CPU 转入目标进程的虚拟地址空间。

## 进程的五大状态

- **运行状态（Running）**：该时刻进程占用 CPU 资源正在执行指令；
- **就绪状态（Ready）**：进程已获得除 CPU 外的一切必要资源，排入就绪队列等待调度器分配 CPU 时间片；
- **阻塞状态（Blocked）**：进程因等待某一事件发生（如等待 I/O 操作完成、等待锁释放等）而暂时停止运行，此时即使分配 CPU 也无法执行；
- **创建状态（New）**：操作系统正在为程序分配资源、初始化 PCB、建立进程描述符；
- **结束状态（Exit）**：进程正常执行结束或因异常终止，正在从系统中注销，等待父进程回收其剩余资源与 PCB。

## 特殊进程

### 僵尸进程（Zombie Process）

僵尸进程是指已经终止执行，但在操作系统的进程表中仍然保留其进程控制块（PCB）的进程。

- **产生原因**：子进程退出时其进程描述符不会被内核立即自动清除，必须由其父进程通过调用 `wait()` 或 `waitpid()` 系统调用读取子进程的退出状态信息后才会被彻底释放。如果子进程已经退出，而父进程一直没有调用 `wait()`，那么子进程的描述符将一直驻留系统中，占用进程号（PID）资源。
- **危害与解决**：大量僵尸进程会耗尽系统的 PID 资源，导致系统无法创建新进程。解决方式是排查父进程的异步通知处理逻辑（如捕获 `SIGCHLD` 信号并执行 wait 清理），或者杀掉父进程使其子进程被 init/systemd 进程接管并自动回收。

### 孤儿进程（Orphan Process）

父进程已经退出或终止，而其一个或多个子进程仍在继续运行，这些子进程就会成为孤儿进程。

- **接管机制**：孤儿进程会被系统顶层守护进程 `init`（PID 为 1 的进程，现代 Linux 通常为 `systemd`）所收养。`init` 进程会作为其新的父进程，并在其终止时规范地执行状态收集和资源清理工作。因此，孤儿进程不会对系统产生危害。

## 进程间通信方式（IPC）

- **管道（Pipe）**：内核中的一串内存缓冲区，数据从一端写入、另一端读出。数据遵循先进先出（FIFO）原则，且只能单向流动（半双工）：
  - **匿名管道**：仅支持具有血缘关系的父子进程或兄弟进程间通信，随进程创建与销毁；
  - **命名管道（FIFO）**：在文件系统中存在对应的文件节点，支持无亲缘关系的任意两个独立进程通信。
- **信号（Signal）**：软件层次上对中断机制的一种模拟，用于异步通知目标进程某个特定事件已经发生（如终端中断 `SIGINT`、强制终止 `SIGKILL` 等）。
- **消息队列（Message Queue）**：保存在内核中的消息链表，消息具有特定的格式和类型。支持独立于发送与接收进程的异步通信，接收方可按消息类型有选择地接收数据。
- **共享内存（Shared Memory）**：由内核开辟一块物理内存，并将其映射到多个进程各自的虚拟地址空间中。**共享内存是所有 IPC 中传输速度最快的方式**，因为进程间无需在内核态与用户态之间进行多余的数据拷贝；但多个进程同时读写时必须配合同步机制（如信号量）来防止数据竞争。
- **信号量（Semaphore）**：一个计数器，用来控制多个进程对临界资源的并发访问：
  - **P 操作（Wait / 申请资源）**：将信号量数值减 1。若值 $\ge 0$ 表示成功获取资源并继续执行；若值 $< 0$ 则进程挂起阻塞，进入该信号量的等待队列；
  - **V 操作（Signal / 释放资源）**：将信号量数值加 1。若值 $\le 0$ 表示队列中仍有阻塞等待的进程，内核唤醒一个等待进程继续执行。
- **套接字（Socket）**：不仅支持本机不同进程间的全双工通信（Unix Domain Socket），更能跨越不同物理网络主机实现分布式进程网络通信。

## 进程调度算法

- **先来先服务（FCFS, First-Come First-Served）**：最简单的非抢占式调度算法。就绪队列按请求 CPU 的先后次序排队执行。缺点是对短任务不利，若长作业排在队首会导致后续所有作业平均等待时间极长（护航效应）。
- **短作业优先（SJF, Shortest Job First）**：优先选择预计执行时间最短的进程执行。能获得最短的系统平均等待时间和周转时间，但缺点是必须提前预估运行时间，且可能导致长作业长期得不到调度而产生“饥饿”现象。
- **优先级调度（Priority Scheduling）**：为每个进程分配优先级，调度器优先调度最高优先级的进程。可分为非抢占式与抢占式两种实现。为避免低优先级进程持续饥饿，通常引入“动态老化”（Aging）策略随等待时间推移提高其优先级。
- **时间片轮转（RR, Round Robin）**：为就绪队列中的每个进程分配一个固定的执行时间片（Quantum）。进程在时间片内运行，若时间片用完但进程未完成，则被强制让出 CPU 并移至队尾等待下一轮调度。保证了所有任务的公平性，适合交互式分时系统。
- **最短剩余时间优先（SRTN, Shortest Remaining Time Next）**：SJF 的抢占式变体。当就绪队列中出现新进程时，若其预计剩余运行时间比当前运行进程的剩余时间更短，调度器立即抢占当前 CPU 并转去执行新进程。
- **多级反馈队列（MLFQ, Multi-Level Feedback Queue）**：综合了优先级调度与时间片轮转。系统设置多个不同优先级的就绪队列，优先级越高的队列时间片越短（如 2ms、4ms、8ms...）。新进程优先进入第一级高优先队列，若在当前时间片内未完成，则被降级移入下一级队列尾部。兼顾了交互式短任务的极速响应与计算密集型长任务的整体吞吐。

# 线程管理

## 线程与进程的核心区别

| 对比维度 | 进程（Process） | 线程（Thread） |
| :--- | :--- | :--- |
| **本质定位** | 操作系统资源分配和拥有的基本单位 | CPU 调度和执行的基本单位 |
| **地址空间** | 每个进程拥有完全独立的虚拟地址空间 | 同一进程内的线程共享进程的虚拟地址空间与代码/数据/堆段 |
| **私有资源** | 拥有独立的文件描述符、信号处理与内存空间 | 仅拥有私有的程序计数器（PC）、寄存器组与栈空间 |
| **切换开销** | 需切换虚拟页表与刷新 TLB，开销较大 | 无需切换页表，仅需保存恢复少量寄存器与栈指针，极其轻量 |
| **健壮与隔离性** | 相互隔离，一个进程崩溃通常不影响其他进程 | 共享内存，一个线程发生段错误非法访问可能导致整个进程崩溃 |
| **生命周期** | 由父进程或系统创建控制 | 随进程而生，进程终止时其内部所有线程自动终止 |

## 线程上下文切换

- **跨进程线程切换**：若切换的两个线程分别属于不同的进程，由于虚拟内存映射不同，其切换开销与完整的进程上下文切换完全相同（需要切换页表 CR3 并刷新 TLB）。
- **同进程线程切换**：若切换的两个线程属于同一个进程，由于虚拟内存地址空间完全共享，虚拟内存资源保持不动，仅需切换线程私有的程序计数器、寄存器和运行栈，开销极小。

## 线程的三种实现方式

- **内核态线程实现（1:1 模型）**：线程完全由内核直接创建和管理调度，内核感知每一个具体线程。多线程可以真正并发映射到多核 CPU 上并行执行；缺点是线程的创建、销毁和切换必须发起系统调用陷入内核态，开销相对偏高（如现代 Linux 的 NPTL）。
- **用户态线程实现（M:1 模型）**：线程在用户空间通过第三方线程库管理，内核对用户线程完全无感知。优点是线程切换在用户态完成，速度极快且消耗资源极低；缺点是无法利用多核 CPU 的并行能力，且一旦某个线程发起阻塞系统调用，整个进程都会被阻塞。
- **混合线程实现（M:N 模型）**：将 $M$ 个用户空间轻量级线程（协程/Goroutine）复用到 $N$ 个内核线程上。用户态运行时负责协程之间的协作调度，内核态负责物理 CPU 核心的真正并行计算，兼具轻量级与多核高并发吞吐（如 Go 语言的 GMP 调度模型）。

## 线程间同步

### 临界区（Critical Section）

对共享资源进行访问与操作的代码片段称为临界区。为了保证并发安全，必须保证临界区的互斥执行（同一时刻只允许一个线程进入临界区）。

### 互斥锁（Mutex）

- **忙等待锁（自旋锁 Spinlock）**：当线程尝试获取锁失败时，不会让出 CPU 进入休眠阻塞，而是在当前 CPU 核心上通过循环指令（`test-and-set`）不断轮询检查锁是否可用。适用于临界区极短、锁持有时间极短的多核场景，避免了线程挂起与唤醒的上下文切换损耗；但若锁持有时间较长，会浪费大量 CPU 算力。
- **无忙等待锁（互斥锁 Mutex）**：当线程尝试获取锁发现已被占用时，主动让出 CPU 控制权，线程状态转为阻塞并挂入等待队列。当锁被释放后，由内核唤醒等待线程重新竞争锁，避免了持续空转带来的 CPU 浪费。

### 信号量（Semaphore）

操作系统提供的基于整型变量的同步原语，用于协调多线程对有限共享资源的受限并发访问。通过不可分割的原子操作 P（减计数）和 V（加计数）控制同时进入临界资源的并发线程上限。

## 死锁（Deadlock）

在两个或多个并发执行的线程中，每个线程都在持有某些资源的同时等待其他线程释放其所占有的资源，在未打破这种僵局之前，所有相关线程都无法继续向前推进，处于无限期相互等待的僵死状态。

### 死锁产生的四个必要条件

1. **互斥条件**：资源在同一时刻只能被一个线程独占使用，其他线程请求该资源只能等待；
2. **请求与保持条件**：线程已至少持有一个资源，但又发出了新的资源申请，而新资源已被其他线程占有，该线程在等待新资源时对自己已获得的资源保持不放；
3. **不剥夺条件**：线程已获取的资源在未使用完毕之前不能被其他线程强行抢占，只能由该线程主动释放；
4. **环路等待条件**：发生死锁时，必然存在一个“线程—资源”的环形等待链（如 $T_0$ 等待 $T_1$ 占用的资源，$T_1$ 等待 $T_0$ 占用的资源）。

### 避免与预防死锁

- **破坏请求与保持条件**：实行资源一次性分配。线程必须在开始执行前一次性申请其所需的全部资源，若不能全部满足则一个都不予分配。
- **破坏不剥夺条件**：当已持有部分资源的线程进一步申请新资源失败时，必须主动释放已持有的所有资源，后续需要时再统一重新申请。
- **破坏环路等待条件**：实行资源的线性有序分配策略。将系统中的所有资源进行唯一编号，所有线程必须严格按照资源编号递增的顺序提出申请，从结构上彻底杜绝环路的形成。

## 活锁与饥饿

- **饥饿（Starvation）**：某个线程因为调度算法不公（如低优先级）或资源分配倾斜，长久无法获得所需的 CPU 时间或资源，导致无法向前推进执行。与死锁不同，处于饥饿中的资源仍有可能在未来某个时刻被分配给该线程。
- **活锁（Livelock）**：处于活锁中的线程都在持续改变自身状态以试图让出资源，但由于各线程之间的反应过于一致或相互礼让，导致整个系统始终无法向前取得实质进展（如两人狭路相逢相互礼让，却总是同时闪向同一侧）。

# 文件系统与硬件存储

## 软链接与硬链接

- **硬链接（Hard Link）**：在目录中创建一个新文件名条目，但其直接指向源文件的同一个 `inode`。每个硬链接会使该 `inode` 的链接计数器加 1。删除任何一个硬链接条目，只要 `inode` 的引用计数不为 0，文件内容就不会丢失。限制：**不能跨越不同的文件系统，且默认不允许对目录创建硬链接**。
- **软链接（符号链接 Symbolic Link）**：一个拥有独立 `inode` 和独立数据块的特殊文件，其数据块内部存储的内容是**源文件的路径字符串**。访问软链接时，操作系统会自动解析并重定向跳转到实际目标文件。特点：**可以跨越不同的文件系统，也可以为目录建立链接**；若源文件被删除，软链接依旧存在，但会变成无法打开的“断链”（Dangling Symlink）。

## 存储介质性能层级

- **机械硬盘（HDD）**：通过物理磁盘盘片高速旋转（如 7200 RPM）和磁头臂物理寻道来定位和读写数据。随机 I/O 极慢，寻道延迟约 5~10ms，顺序传输速率约 100~200 MB/s。
- **固态硬盘（SSD）**：基于闪存介质（NAND Flash）与主控芯片，无任何机械活动部件。访问延迟约 50~100μs（比 HDD 快上百倍），NVMe SSD 顺序读写可达数千 MB/s，高并发随机读写性能极佳。
- **物理内存（RAM）**：基于电容和半导体电路的高速易失性存储介质。访问延迟约 10~100ns（比 HDD 快 10 万倍以上），数据带宽可达数十至数百 GB/s。

# I/O 模型与 I/O 多路复用

## 阻塞 I/O vs 非阻塞 I/O

- **阻塞 I/O（Blocking I/O）**：当应用程序调用 `read()` 时，如果内核数据尚未准备就绪，调用线程会被操作系统挂起，一直等到内核数据准备完成并从内核空间拷贝到用户空间缓冲区后，系统调用才返回。阻塞过程涵盖了“等待数据就绪”和“内核数据拷贝到用户态”两个完整阶段。
- **非阻塞 I/O（Non-blocking I/O）**：当应用程序发起 `read()` 时，若内核数据尚未就绪，调用立即返回错误码（如 `EAGAIN` / `EWOULDBLOCK`），线程不会被挂起。应用程序必须通过不断循环轮询（Polling）检测内核数据是否准备好。在数据未就绪期间会持续空转消耗 CPU 资源。

## I/O 多路复用

在传统的阻塞多线程/多进程模型中，服务端为每个客户端连接都分配一个线程，连接数过高时会导致系统线程上下文切换开销爆炸、内存不堪重负。

**I/O 多路复用** 允许单个进程/线程同时监视多个 Socket 文件描述符（FD）。当某个或某些 Socket 产生可读或可写事件时，通知应用程序进行定向处理，实现“一个线程处理成千上万并发连接”。

### select

- **工作机制**：将所有需要监控的 Socket 放入一个固定长度的位图集合 `fd_set` 中，随后调用 `select()` 将该集合全量拷贝到内核空间。内核遍历集合检查各个 Socket 是否有事件发生，若有则打上标记，再将修改后的 `fd_set` 全量拷贝回用户空间。用户程序仍需再次通过 $O(n)$ 线性循环遍历整个集合，找出可读写的 Socket 进行处理。
- **劣势与瓶颈**：
  1. **描述符数量限制**：使用固定长度位图，受内核常量 `FD_SETSIZE` 限制，默认最大只能监听 1024 个文件描述符；
  2. **双向内存拷贝开销**：每次调用都必须把全量 `fd_set` 从用户态拷贝到内核态，再从内核态拷贝回用户态，高并发下内存拷贝损耗巨大；
  3. **双重线性遍历**：内核态与用户态均需要对整个 `fd_set` 集合进行 $O(n)$ 遍历，当连接数很多但活跃连接很少时，效率极低；
  4. **重复重置工作**：每次调用返回后 `fd_set` 均被修改，下一次调用必须全量重新填充。

### poll

- **工作机制**：使用动态结构体数组（`struct pollfd`）代替固定位图组织描述符，突破了 1024 的硬上限限制。
- **劣势与瓶颈**：本质机制与 `select` 相同，仍然依赖线性扫描与全量内存拷贝，随着监听连接数的增多，性能依旧呈线性下降。

### epoll（Linux 解决 C10K 问题的核心）

epoll 彻底颠覆了 select/poll 的轮询模式，通过两项重大技术创新解决了海量连接瓶颈：

1. **红黑树管理监听描述符**：epoll 在内核中维护了一棵红黑树来跟踪所有待监控的 Socket。程序通过 `epoll_ctl()` 增、删、改单个 Socket，增删改查时间复杂度为 $O(\log n)$。不需要像 select/poll 那样每次调用都全量传入整个描述符集合，彻底消除了海量描述符在内核态与用户态之间的重复拷贝。
2. **事件就绪链表与回调驱动机制**：epoll 采用事件驱动机制。当某个 Socket 产生 I/O 事件时，网卡驱动的中断处理程序通过内核回调函数，直接将该就绪 Socket 追加到一个双向就绪链表（Ready List）中。当程序调用 `epoll_wait()` 时，只返回当前就绪链表中的描述符，时间复杂度为 $O(1)$，无需遍历整个监听集合。
3. **支持水平触发（LT）与边缘触发（ET）**：
   - **LT（Level Triggered，水平触发，默认）**：只要缓冲区还有未读/未写数据，每次调用 `epoll_wait` 都会重复通知；
   - **ET（Edge Triggered，边缘触发）**：仅在状态发生变化（从未就绪变为就绪）时通知一次，要求应用程序必须一次性将缓冲区读写完毕（通常搭配非阻塞 I/O 使用），能大幅减少系统调用唤醒次数，实现极高的系统吞吐。

# 内存管理

## 物理内存 vs 虚拟内存

- **物理内存（Physical Memory）**：计算机中真实安装的 RAM 硬件模块。应用程序和操作系统最终的指令与数据都必须载入物理内存中才能被 CPU 执行。
- **虚拟内存（Virtual Memory）**：操作系统与硬件（MMU）协同提供的一种内存抽象技术。它让每个进程都认为自己独占一份连续、完整的私有地址空间：
  - **隔离性**：每个进程运行在专属的虚拟地址空间中，即使指针越界或非法访问也不会窜改其他进程或内核的数据；
  - **地址转换**：CPU 内部的内存管理单元（MMU）通过**页表（Page Table）**将虚拟地址动态转换为真实的物理内存地址；
  - **空间扩充**：当实际物理内存不足时，操作系统将暂时不用的虚拟内存页换出到磁盘交换区（Swap），从而支撑比物理内存大得多的应用程序运行。

## 内存分段与内存分页

### 内存分段（Segmentation）

按照程序的逻辑结构划分（如代码段、数据段、堆段、栈段等）。每个段具有不同的读写属性与逻辑意义。虚拟地址由“段号 + 段内偏移量”组成，通过段表映射到物理地址。
- **缺点**：容易产生严重的**外部碎片**（由于段的长度不固定，频繁分配与回收会导致物理内存中零散留下许多无法被利用的空闲小碎块）。

### 内存分页（Paging）

将虚拟地址空间和物理内存空间严格切分为固定大小的块。连续且固定大小的虚拟空间称为**页（Page）**，物理内存对应的固定块称为**页帧（Page Frame）**。在 Linux x86 架构下，默认每页大小为 **4KB**。
- **优势**：消除了外部碎片，物理页帧无需连续分配。
- **缺点**：页内可能会存在未用满的**内部碎片**；且访问内存数据时通常需要两次寻址（第一次查页表获取物理页号，第二次根据物理地址获取实际数据）。

### 分页与分段的本质区别

| 对比维度 | 内存分页 | 内存分段 |
| :--- | :--- | :--- |
| **划分目的** | 物理管理单位，为了提高内存利用率，对用户透明 | 逻辑信息单位，符合程序逻辑结构，对用户可见 |
| **大小特征** | 大小严格固定（系统默认 4KB） | 大小动态不固定，由逻辑功能决定 |
| **地址空间** | 一维连续虚拟地址空间 | 二维地址空间（段名 + 段内偏移量） |
| **共享与保护** | 页边界无逻辑意义，保护和共享受限 | 段具有明确逻辑属性，易于实现代码共享与权限保护 |
| **碎片特征** | 产生页内内部碎片，无外部碎片 | 产生外部碎片，无内部碎片 |

## 多级页表与快表

- **多级页表（Multi-level Page Table）**：在 32 位或 64 位大地址空间下，若采用单级页表，单级页表自身就要占据庞大的连续物理空间。多级页表通过树状多层结构组织页表，仅在进程实际用到某个区间的虚拟地址时才按需动态分配对应的次级页表项，极大降低了页表常驻内存的物理开销。
- **快表（TLB, Translation Lookaside Buffer）**：由于多级页表寻址每次访存需要逐层查询多次页表（如 4 级页表需 4 次查表 + 1 次读写数据），导致系统性能损耗。基于程序的局部性原理，CPU 芯片内部集成了超高速的高速缓冲硬件 TLB（快表），用于缓存最近最常访问的虚拟页号到物理页帧的映射条目。TLB 命中时可在单时钟周期内直接完成地址转换。

## 交换空间（Swap Space）

操作系统在磁盘上开辟的一块独立存储分区或文件。当物理 RAM 内存资源紧张时，内核将某些暂时不活跃的内存页数据转移到磁盘交换区中暂存，以释放出宝贵的物理 RAM 供前台活跃进程使用。物理内存容量与交换空间容量的总和构成了虚拟内存可用的理论上限。

## 缺页中断（Page Fault）

当 CPU 访问某个虚拟地址时，硬件 MMU 查询页表发现该虚拟页尚未载入物理内存（页表项中的有效位为 0），CPU 立即触发一次硬件异常——**缺页中断**。操作系统内核介入并执行以下恢复流程：

1. 检查访问地址是否合法，若越界或无权限则触发段错误（Segmentation Fault）；
2. 操作系统在物理内存中寻找空闲页帧；若无空闲页帧，则触发页面置换算法淘汰某页；
3. 将所需页面从磁盘（Swap 分区或原始可执行文件）读取并加载到分配的物理页帧中；
4. 更新页表映射条目，将有效位标记为有效；
5. 恢复中断现场，CPU 重新执行先前被中断的访存指令。

## 常见页面置换算法

- **最佳页面置换算法（OPT, Optimal）**：淘汰未来最长时间内不会被访问的页面。能保证理论上最低的缺页率，但由于无法预知未来的访问序列，实际系统中无法实现，常作为衡量其他算法优劣的基准上限。
- **先进先出置换算法（FIFO, First-In First-Out）**：优先淘汰最早进入内存的页面。实现极其简单（基于队列管理），但可能出现 **Belady 异常**（分配给进程的物理页帧增加，缺页率反而升高的反常现象），且容易误淘汰常驻的高频页面。
- **最近最久未使用置换算法（LRU, Least Recently Used）**：淘汰过去最长时间未被访问过的页面。基于局部性原理，效果最接近 OPT 算法。但精确实现需要硬件计时器或频繁维护访问链表，系统开销较大。
- **时钟页面置换算法（Clock / 二次机会算法）**：LRU 的一种高效近似工程实现。将所有内存页组织为循环链表（形如时钟表盘），每个页面设置一个访问位（访问时置 1）。指针顺时针巡检：若访问位为 1 则清零并给予“二次机会”跳过；若访问位为 0 则直接选中该页进行置换。
- **最不常用置换算法（LFU, Least Frequently Used）**：统计各页面被访问的累计频次，置换掉过去访问次数最少的页面。需要为每个页面维护访问计数器并设计定期衰减机制。

# 系统结构与内核态/用户态

## 内核与内存区域划分

操作系统的**内核（Kernel）**是整个系统底层的核心控制程序，拥有对底层硬件资源的绝对控制权。为了防止应用程序误操作破坏系统全局稳定，CPU 与操作系统通过特权级别将内存分为两大区域：

- **用户空间（User Space / 用户态）**：为用户应用程序分配的受限内存区域。用户态下的进程无法直接执行特权指令（如关中断、修改页表寄存器），也不能直接访问物理硬件设备和内核数据结构。
- **内核空间（Kernel Space / 内核态）**：操作系统内核代码与底层核心运行时数据结构所在的特权内存区域，拥有对所有物理内存和底层硬件的完全访问控制权。

## 用户态与内核态的切换（系统调用）

当运行在用户态的应用程序需要执行底层特权操作（如文件读写 `read`/`write`、创建进程 `fork`、分配虚拟内存 `mmap`、网络收发 `socket` 等）时，必须通过**系统调用（System Call）**陷入内核：

1. **触发陷阱指令**：用户程序准备好系统调用号与参数后，触发软中断或陷阱指令（如 x86-64 的 `syscall` 指令）；
2. **CPU 特权级切换**：CPU 硬件自动从用户态（Ring 3）切换至内核态（Ring 0），将用户态的程序计数器（RIP）、栈指针（RSP）及寄存器现场保存在内核栈中；
3. **分发与执行**：内核根据系统调用号查阅系统调用表（Syscall Table），跳转执行对应的内核服务例程；
4. **返回用户态**：执行完毕后将结果存入寄存器，从内核栈中恢复用户态上下文现场，执行返回指令（如 `sysret`）切回用户态继续向下执行。
